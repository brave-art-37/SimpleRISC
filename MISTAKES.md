# Debugging Log

1. **byte-addressed vs word-addressed confusion**

   * initially used `PC + 4`
   * initially indexed memory with `address[11:2]`
   * SimpleRISC implementation is word-addressed
   * corrected to `PC + 1` and `address[9:0]`

2. **wrong destination-register bit field**

   * initially used `instruction[26:23]`
   * actual SimpleRISC destination field for the tested encoding is `[25:22]`

3. **MOV immediate used the wrong ALU operand**

   * MOV was connected to the first operand
   * for immediate MOV, it needed the selected second-operand/immediate path

4. **U-mode immediate was incorrectly sign-extended**

   * used sign extension for the normal/U immediate path
   * U-mode needed zero extension

5. **NOP test encoding was wrong**

   * accidentally constructed a 31-bit instruction
   * resulting leading bit shift changed the opcode
   * got `0x34000000` instead of the NOP encoding

6. **RET branch-taken condition was incomplete**

   * RET selected the return address as its target
   * but `is_branch_taken` didn't include `is_return`
   * therefore the target wasn't actually sent to the PC

7. **CALL was initially treated incorrectly for branching**

   * CALL needed to behave as an unconditional branch
   * `is_unconditional_branch` needed to include CALL

8. **CALL return address was initially off by one**

   * initially thought return address was `PC + 1`
   * delayed branching means the instruction after CALL executes as the delay slot
   * therefore return address is `PC + 2` in the word-addressed implementation

9. **writeback destination for CALL**

   * CALL doesn't write to the encoded destination register
   * return address goes to fixed `R15`

10. **persistent flags timing bug**

* initially used `is_cmp` from the current control unit
* but flags are generated by the CMP instruction in EX
* flag-register write enable therefore had to use `is_cmp_from_OFEX`

11. **ALU interface mismatch**

* CPU tried to pass `is_nop` into ALU even though ALU had no such input
* removed the unnecessary connection

12. **`mux3` select construction**

* initially constructed the select using arithmetic shifts on 1-bit signals
* width truncation caused problems
* fixed by treating `{s[2], s[1], s[0]}` as the 3-bit index

13. **branch target/addressing assumptions**

* early branch-target logic assumed byte-addressed `<< 2`
* current implementation is word-addressed, so that assumption had to be removed/corrected
